# TypeScript Utility Types Explained: Partial, Pick, Omit, and Record

TypeScript includes utility types that transform existing types. They help developers reuse model definitions instead of creating nearly identical interfaces for every API request, response, or application state.

Utility types operate at compile time. They do not validate or transform runtime objects automatically.

## Partial<T>

Partial makes every property in a type optional.

~~~typescript
type User = {
  id: number;
  name: string;
  email: string;
};

type UserUpdate = Partial<User>;
~~~

UserUpdate can contain only the fields being changed.

This is convenient for update operations, but the application must still validate that the requested update is meaningful and permitted.

## Required<T>

Required makes the properties of a type required:

~~~typescript
type Preferences = {
  theme?: string;
  language?: string;
};

type CompletePreferences = Required<Preferences>;
~~~

The resulting type requires both fields.

## Readonly<T>

Readonly makes properties read-only through the resulting type:

~~~typescript
type Config = {
  host: string;
  port: number;
};

type FixedConfig = Readonly<Config>;
~~~

This is a compile-time restriction. It does not deeply freeze nested objects or prevent mutation through another reference.

## Pick<T, Keys>

Pick creates a type containing only selected properties:

~~~typescript
type User = {
  id: number;
  name: string;
  email: string;
  passwordHash: string;
};

type PublicUser = Pick<User, "id" | "name">;
~~~

This is useful for defining a limited public view of a model.

It does not automatically remove fields from a runtime object. Explicitly construct the public response so sensitive properties are not serialized.

## Omit<T, Keys>

Omit creates a type excluding selected properties:

~~~typescript
type CreateUser = Omit<User, "id">;
~~~

This can be useful when an identifier is generated by the server.

Again, a type transformation does not perform runtime object filtering.

## Record<Keys, Type>

Record creates an object type whose keys and values are described by specified types:

~~~typescript
type Environment = "dev" | "test" | "prod";

type ApiUrls = Record<Environment, string>;
~~~

An ApiUrls value must provide a string for each key in the Environment union.

Record is useful for lookup tables, configuration maps, and dictionaries with known key sets.

## Exclude and Extract

Exclude removes union members assignable to another type:

~~~typescript
type Status = "draft" | "published" | "archived";
type EditableStatus = Exclude<Status, "archived">;
~~~

Extract keeps only union members assignable to another type:

~~~typescript
type ActiveStatus = Extract<Status, "published" | "draft">;
~~~

These utilities are useful for building narrower type variants.

## ReturnType and Parameters

ReturnType extracts the return type of a function:

~~~typescript
function createUser() {
  return { id: 1, name: "Asha" };
}

type CreatedUser = ReturnType<typeof createUser>;
~~~

Parameters extracts a function's parameter tuple:

~~~typescript
type CreateUserArgs = Parameters<typeof createUser>;
~~~

These utilities help maintain relationships between function declarations and other type definitions.

## NonNullable<T>

NonNullable removes null and undefined from a type:

~~~typescript
type MaybeName = string | null | undefined;
type Name = NonNullable<MaybeName>;
~~~

This can be useful after a value has been checked for existence, though the runtime check is still required.

## Utility types and API models

Utility types can reduce repetition between create, update, response, and internal model types.

Avoid using one large model for every boundary. An API response should expose only intended fields, and request types should express the actual contract for that operation.

## Common mistakes

### Assuming Pick or Omit changes runtime data

These are type transformations. Construct or transform real objects explicitly.

### Using Partial for every update API

Some update operations require at least one field or specific field combinations. Add validation and a more precise type when necessary.

### Treating Readonly as runtime immutability

Readonly restricts assignments through a TypeScript type. It does not freeze an object.

### Overusing complex utility combinations

Keep public types understandable. Extract a named type when a long composition becomes difficult to read.

## Frequently asked questions

### Are utility types built into TypeScript?

Yes. Common utilities such as Partial, Required, Pick, Omit, Record, ReturnType, and Parameters are included in the standard library.

### Can I create custom utility types?

Yes. Mapped types, conditional types, and keyof allow developers to create reusable type transformations.

### Do utility types validate JSON responses?

No. They only describe compile-time types. Runtime validation requires separate logic.
